## Summary
Implemented a complete PM approval workflow for the admin panel. New product-manager registrations are now created inactive (pending admin approval) via `User.save()`. The admin dashboard gained a "Pending PM Approvals" card with inline accept/reject and a link to a new dedicated PM detail page that shows the full profile and verification document. All admin mutations (PM accept/reject, dispute resolution) now write `AuditLog` rows per project rule R6. Panel templates were reorganized into logical `pm/` and `disputes/` subfolders for clarity.

## Details
### accounts/models.py
- In `User.save()`, the `PRODUCT_MANAGER` branch now includes: `if self._state.adding: self.is_active = False`. This makes registration approval meaningful while leaving already-active PMs untouched on subsequent saves.

### panel/views.py
- `AdminDashboardView.get_context_data`: queries `User.objects.filter(role='product_manager', is_active=False)` and exposes `pending_pms` (first 5) and `pending_pm_count`.
- New `PMDetailView` (`role_required('admin')`, `TemplateView`) loads the PM by pk and renders `panel/pm/detail.html`.
- `AcceptPMView`/`RejectPMView`: after mutating `is_active`, create an `AuditLog` row (`action='user.pm_accepted'` / `'user.pm_rejected'`, `table_name=AuditLog.TableType.USER`) capturing the acting admin and request IP.
- `DisputeResolveView.form_valid`: after saving, creates an `AuditLog` row (`action='dispute.resolved'`, `table_name=AuditLog.TableType.DISPUTE`) with status/resolution.
- `PendingPMListView.template_name` changed to `'panel/pm/pending.html'`.

### panel/urls.py
- Added `path('pm/<int:pk>/', views.PMDetailView, name='pm_detail')` between the pending list and accept/reject routes.

### Templates
- `dashboard.html`: third row is now Pending PM Approvals (left) + Open Disputes (right); a full-width Quick Actions row follows with a "PM Approvals" button. Recent Users rows link pending PMs to `panel:pm_detail`.
- `pm/pending.html`: card-based layout consistent with the rest of the panel, each card links to detail and offers Accept/Reject.
- `pm/detail.html`: two-column layout — account details (email, phone, region, address, joined, verified/active/staff badges, verification-doc link) and an Approval actions column.
