- **Date**: 2026-08-22
- **Agent**: swe
- **Objective**: Fix how a Product Manager finds and claims batches to verify — make the `under_review` status actually used (via an explicit "Start Review" claim) and prevent two PMs from verifying the same batch, with audit logging. Rejection was intentionally out of scope.
- **Status**: Completed (code changes applied; DB migration + test run deferred — shell environment unavailable)

## Summary
Added a claim mechanism so a PM "takes ownership" of a batch before verifying it. A new `claimed_by` / `claimed_at` field on `Batch` records who is reviewing. The PM dashboard's Pending list now offers a **Start Review** button (POST) that claims the batch (`status=under_review`, `claimed_by=me`) and routes to the verify page. `BatchVerifyView.post` now locks the row (`select_for_update`), blocks verification if another PM has claimed the batch, and implicitly claims an unclaimed batch. Both claim and verify write `AuditLog` rows. The "Under Review" dashboard column now shows who claimed each batch and only lets the claimer Verify.

## Details
### farmer/models.py
- `claimed_by = models.ForeignKey(settings.AUTH_USER_MODEL, on_delete=models.SET_NULL, null=True, blank=True, related_name='claimed_batches', limit_choices_to={'role': 'product_manager'})`
- `claimed_at = models.DateTimeField(null=True, blank=True)`

### pm/views.py
- `StartReviewView` (POST): `transaction.atomic()` + `Batch.objects.select_for_update().get(pk=...)`; blocks if already verified or claimed by another PM; else sets `status=UNDER_REVIEW`, `claimed_by=request.user`, `claimed_at=now`; writes `AuditLog(action='batch.claimed', table_name=AuditLog.TableType.BATCH)`. GET redirects to verify.
- `BatchVerifyView.post`: locks row; if `under_review` and `claimed_by` is another PM → block with warning; if `pending`/`under_review` and unclaimed → claim to current PM; on valid form saves `QualityVerification`, sets `VERIFIED`, writes `AuditLog(action='batch.verified', ...)`.

### pm/templates/pm/dashboard.html
- Pending action cell is now `<form method="post" action="{% url 'pm:batch_start_review' batch.pk %}">` with a CSRF-protected "Start Review" button.
- Under Review action cell branches on `batch.claimed_by_id` vs `request.user.pk`.

### pm/templates/pm/batches/verify.html
- New `{% elif batch.status == 'under_review' and batch.claimed_by_id and batch.claimed_by_id != request.user.pk %}` branch renders a blocking notice.
