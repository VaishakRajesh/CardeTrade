## Summary
Added a generic admin "User Detail" page (`panel:user_detail`) that displays the full profile of any user (farmer, trader, PM, or admin) in the same visual style as the PM detail page, but read-only. From that page an admin can **Revoke Access** (deactivate) or **Reactivate** an account; self-revocation is blocked. Every username in the dashboard's Recent Users table now links to this page. All mutations write `AuditLog` rows. No PM-approval code was removed or altered.

## Details
### panel/views.py
- `UserDetailView`: `@role_required('admin')`, `TemplateView`, loads any `User` by pk, exposes as `u`.
- `RevokeUserView`: POST; `get_object_or_404(User, pk=...)`; if `user.pk == request.user.pk` → error + redirect (no change); else `is_active=False`, then `AuditLog` (`action='user.revoked'`, `table_name=AuditLog.TableType.USER`).
- `ReactivateUserView`: POST; `is_active=True`, then `AuditLog` (`action='user.reactivated'`).

### panel/urls.py
- Three new routes inserted before the Disputes block; PM routes unchanged.

### panel/templates/panel/user_detail.html
- Mirrors `pm/detail.html` layout. Uses `request.user.pk` to hide the Revoke button for the admin's own account. Revoke form includes a JS `confirm()` guard.

### panel/templates/panel/dashboard.html
- The Recent Users `<td>` now wraps the username in a link to `panel:user_detail` (previously only pending PMs linked to `pm_detail`).
